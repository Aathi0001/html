DP fundamentals

Dynamic Programming avoids solving the same subproblem repeatedly by storing answers and reusing them.

Memoization (top-down)

Start with a recursive definition. Cache each result the first time it is computed.

from functools import lru_cache

@lru_cache(None)
def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)

Tabulation (bottom-up)

Start with base cases and fill a table in dependency order.

def fib(n):
    if n <= 1:
        return n
    dp = [0] * (n + 1)
    dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]

How to recognize DP

  • Overlapping subproblems: the same smaller question appears repeatedly.
  • Optimal substructure: an answer can be assembled from answers to smaller states.
  • State: enough information to identify a subproblem.
  • Transition: a recurrence that combines smaller states.

Practice routine

  1. Write the state meaning in one sentence.
  2. Write base cases before loops.
  3. Describe the transition.
  4. Determine iteration order.
  5. Dry-run a small example.
  6. Analyze time and space complexity.
Floyd–Warshall is included because its repeated “allow intermediate vertex k” update is a classic DP recurrence.
