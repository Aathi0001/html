Rabin–Karp Algorithm

Learn how hashing and rolling hash help find a pattern inside a text, with a step-by-step interactive dry run.

1. What is Rabin–Karp?

Rabin–Karp is a string pattern-matching algorithm that uses hash values to find a pattern in a larger text.

Instead of comparing every character at every possible position immediately, it first compares the hash of the pattern with the hash of each text window of the same length.

Text

ABCCDABC

Pattern

ABC

Result

Match at index 5

Main idea: compare hash values first. When hashes match, compare the actual characters to confirm the match.

2. What is hashing?

A hash function converts a string into a number. That number is called the string's hash value.

For this learning example, imagine each character has a number:

CharacterExample value
A1
B2
C3

For a simple illustrative hash, add the character values.

ABC = 1 + 2 + 3 = 6
CAB = 3 + 1 + 2 = 6

Notice that ABC and CAB have the same hash, even though the strings are different. This is called a hash collision.

Therefore, a matching hash does not guarantee a matching string. Rabin–Karp verifies the actual characters when the hashes match. Real implementations generally use a polynomial rolling hash with modular arithmetic rather than this simple sum.

3. What is a rolling hash?

Suppose the text is ABCCDABC and the pattern is ABC. The pattern length is 3, so we inspect text windows of length 3.

WindowWindow hash (simple example)
ABC1 + 2 + 3 = 6
BCC2 + 3 + 3 = 8
CCD3 + 3 + 4 = 10

A rolling hash calculates the next window's hash by reusing the previous window's information. It removes the outgoing character and adds the incoming character, with position weighting handled by the rolling-hash formula.

For a proper polynomial rolling hash, moving from one window to the next can be done in constant time. That is what makes the algorithm efficient.

5. Python implementation

This version uses a polynomial rolling hash with base 256 and prime modulus 1,000,000,007. It returns the index of the first match or -1 if no match is found. 

def rabin_karp(text, pattern):
    n = len(text)
    m = len(pattern)

    if m == 0:
        return 0

    if m > n:
        return -1

    base = 256
    mod = 1_000_000_007

    highest = pow(base, m - 1, mod)

    pattern_hash = 0
    window_hash = 0

    # Calculate the first window and pattern hashes.
    for i in range(m):
        pattern_hash = (
            pattern_hash * base + ord(pattern[i])
        ) % mod

        window_hash = (
            window_hash * base + ord(text[i])
        ) % mod

    # Slide the window across the text.
    for start in range(n - m + 1):

        # Hashes match: verify actual characters.
        if pattern_hash == window_hash:
            if text[start:start + m] == pattern:
                return start

        # Calculate the next window's rolling hash.
        if start < n - m:
            outgoing = ord(text[start])
            incoming = ord(text[start + m])

            window_hash = (
                (window_hash - outgoing * highest) * base
                + incoming
            ) % mod

            # Python's modulo operation keeps it non-negative.
            window_hash %= mod

    return -1


text = "ABCCDABC"
pattern = "ABC"

print(rabin_karp(text, pattern))
# Output: 5
Why verify characters? Two different strings can produce the same hash. Checking the substring prevents a collision from being incorrectly reported as a real match.

6. Complexity analysis

Let n be the text length and m the pattern length.

CaseTime complexityReason
Expected / averageO(n + m)Rolling hashes are updated in constant time, and few windows require full verification.
Worst caseO(n × m)Many hash matches may require character-by-character verification.
Extra spaceO(1)The implementation uses a fixed number of hash variables.

The expected running time depends on hash behavior and the frequency of collisions. The worst-case bound matters when many windows collide or repeatedly match long prefixes.

7. When should you use Rabin–Karp?

Useful for

  • Searching for a substring
  • Searching for multiple patterns with related lengths
  • Plagiarism and duplicate-text detection techniques
  • Finding repeated sequences in text

Be careful about

  • Hash collisions
  • Choosing a suitable hash base and modulus
  • Verifying characters when hashes match
  • Worst-case performance

9. Quick self-test

1. What does Rabin–Karp compare first?

It compares the hash of the pattern with the hash of the current text window.

2. What is a hash collision?

Different strings producing the same hash value.

3. Why verify characters when hashes match?

Because equal hashes do not prove that the strings are equal.

4. What is the rolling hash benefit?

It lets the next window's hash be calculated from the previous one without hashing every character again.

5. What is the worst-case time complexity?

O(n × m), when many windows need full character verification.
