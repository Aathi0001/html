0. Start here: what is searching?

Searching means checking whether a value exists in a collection and, if it does, finding its position (index). For example, find 30 in [10, 20, 30, 40]. Its index is 2, because Python indexes start at zero.

Unsorted data

Example: [40, 10, 30, 20]. Linear Search works without rearranging the list.

Sorted data

Example: [10, 20, 30, 40]. Binary Search and several other methods can skip portions of the list.

Learning order: Linear Search first, then Binary Search. Learn the other methods after you are comfortable with those two.

Search terms to know

  • Target: the value you want to find.
  • Index: the position number, starting from 0.
  • Comparison: checking a list value against the target.
  • Sorted: values are ordered, such as smallest to largest.
  • Return: send a result back to the caller. Here, we return the index or -1 if not found.

1. Linear Search

Works on unsorted dataBeginner-friendly

Idea: start at the first item and check each item one by one. Stop when the target is found or when there are no items left.

Example dry run

List: [8, 4, 11, 6], target: 11

StepIndexValueDecision
1088 ≠ 11, continue
2144 ≠ 11, continue
321111 = 11, found at index 2

Python code

def linear_search(nums, target):
    for i in range(len(nums)):
        if nums[i] == target:
            return i
    return -1

print(linear_search([8, 4, 11, 6], 11))  # 2
print(linear_search([8, 4, 11, 6], 5))   # -1

Complexity

  • Best: O(1) — the first item matches.
  • Average: O(n) — typically checks a portion of the list proportional to its length.
  • Worst: O(n) — target is last or missing, so every item may be checked.
  • Extra space: O(1) — only a few variables are needed.
Use it when: the list is small, data is unsorted, or you only need a simple reliable search. Don't expect: it to skip ahead in a large list.

2. Binary Search

Requires sorted dataO(log n) time

Idea: inspect the middle item. If it is the target, stop. If the target is smaller, discard the right half; if larger, discard the left half. Repeat on the remaining half.

Important: Binary Search is only valid when the data is sorted according to the same ordering used for comparison.

Example dry run

Sorted list: [3, 6, 9, 14, 18, 27, 31], target: 18.

Steplowhighmid = (low + high) // 2Decision
1063 → value 1418 > 14, set low = 4
2465 → value 2718 < 27, set high = 4
3444 → value 18Found at index 4

Python code

def binary_search(nums, target):
    low = 0
    high = len(nums) - 1

    while low <= high:
        mid = (low + high) // 2

        if nums[mid] == target:
            return mid
        elif nums[mid] < target:
            low = mid + 1
        else:
            high = mid - 1

    return -1

print(binary_search([3, 6, 9, 14, 18, 27, 31], 18))  # 4

Why use low <= high?

The range still contains a candidate when low == high: exactly one index remains. Once low > high, the search range is empty and the target is absent.

Complexity

  • Best: O(1) — the middle item matches immediately.
  • Average: O(log n) — each comparison roughly halves the remaining range.
  • Worst: O(log n) — repeatedly halves until found or absent.
  • Extra space: O(1) for this iterative version.
Use it when: data is sorted and you need fast lookups. If data changes often, consider the cost of keeping it sorted.

3. Jump Search

Requires sorted data

Idea: jump forward in fixed-size blocks, often about √n. When a block's end reaches or passes the target, search that block linearly.

Python code

from math import isqrt

def jump_search(nums, target):
    n = len(nums)
    if n == 0:
        return -1

    step = isqrt(n) or 1
    start = 0
    end = step

    while start < n and nums[min(end, n) - 1] < target:
        start = end
        end += step
        if start >= n:
            return -1

    for i in range(start, min(end, n)):
        if nums[i] == target:
            return i
        if nums[i] > target:
            return -1
    return -1

Complexity: best O(1); average/worst O(√n) comparisons; extra space O(1). It can be useful on sorted arrays when block jumps are convenient, though Binary Search is usually the simpler default.

4. Interpolation Search

Requires sorted numeric data

Idea: instead of always checking the middle, estimate where the target should be based on its value. This works best when values are distributed fairly uniformly.

Watch out: duplicate values, uneven distributions, and equal values at both ends need careful handling. The code below guards against division by zero.

Python code

def interpolation_search(nums, target):
    low, high = 0, len(nums) - 1

    while low <= high and nums and nums[low] <= target <= nums[high]:
        if nums[low] == nums[high]:
            return low if nums[low] == target else -1

        pos = low + int(
            (target - nums[low]) * (high - low)
            / (nums[high] - nums[low])
        )

        if nums[pos] == target:
            return pos
        if nums[pos] < target:
            low = pos + 1
        else:
            high = pos - 1

    return -1

Complexity: average O(log log n) on uniformly distributed values; worst O(n); extra space O(1). This is a specialized option, not a general replacement for Binary Search.

5. Exponential Search

Requires sorted data

Idea: check indexes 1, 2, 4, 8, 16… until the value is large enough or the end is reached. Then run Binary Search inside the bracket found.

Python code

def exponential_search(nums, target):
    n = len(nums)
    if n == 0:
        return -1
    if nums[0] == target:
        return 0

    bound = 1
    while bound < n and nums[bound] < target:
        bound *= 2

    low = bound // 2
    high = min(bound, n - 1)

    while low <= high:
        mid = (low + high) // 2
        if nums[mid] == target:
            return mid
        if nums[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return -1

Complexity: O(log n) worst-case time and O(1) extra space for this iterative implementation. It is useful when the target may be near the beginning or when searching a sorted collection whose length is not known in advance.

6. Fibonacci Search

Requires sorted data

Idea: like Binary Search, it reduces the candidate range, but it chooses probe positions using Fibonacci numbers instead of splitting exactly in half.

Python code

def fibonacci_search(nums, target):
    n = len(nums)
    fib2, fib1, fib = 0, 1, 1

    while fib < n:
        fib2, fib1 = fib1, fib
        fib = fib1 + fib2

    offset = -1
    while fib > 1:
        i = min(offset + fib2, n - 1)

        if nums[i] < target:
            fib, fib1, fib2 = fib1, fib2, fib1 - fib2
            offset = i
        elif nums[i] > target:
            fib, fib1, fib2 = fib2, fib1 - fib2, fib2 - (fib1 - fib2)
        else:
            return i

    if fib1 and offset + 1 < n and nums[offset + 1] == target:
        return offset + 1
    return -1

Complexity: O(log n) worst-case time and O(1) extra space. It is less commonly chosen in everyday Python than Binary Search, but it is useful to know as a search strategy and for understanding alternative ways to shrink a range.

Complexity basics

O(1) — constant

Work stays roughly the same as the list grows. Example: checking one known index.

O(log n) — logarithmic

Each step shrinks the search area by a fraction, often half. If the input doubles, only about one extra halving step is needed.

O(√n) — square root

Work grows with the square root of the list length. Jump Search uses blocks of roughly √n.

O(n) — linear

Work grows in proportion to the number of items. In the worst case, Linear Search checks all n items.

What does “space complexity” mean?

It describes extra memory used by the algorithm, not the memory already occupied by the input list. The iterative versions in these notes generally use O(1) extra space: a few index variables regardless of list length.

Which search should I choose?

  1. Unsorted list? Start with Linear Search, or sort first if you will search many times and sorting is worth the cost.
  2. Sorted list? Binary Search is usually the best first choice.
  3. Sorted numeric values spread fairly evenly? Interpolation Search may be worth considering.
  4. Need to find a range quickly in a sorted, potentially unbounded sequence? Exponential Search can bracket the target.
  5. Studying alternative methods? Learn Jump and Fibonacci Search after Linear and Binary Search.
Practical Python note: for membership in many repeated lookups, a set or dict may be more suitable than repeatedly scanning a list. For sorted lists, Python's bisect module provides binary-search insertion-point tools.
