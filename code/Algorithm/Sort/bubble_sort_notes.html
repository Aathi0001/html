Bubble Sort

A beginner-friendly sorting algorithm that repeatedly compares neighboring values and swaps them when they are in the wrong order.

● Beginner friendly
In-placeStableAscending orderO(n²) basic version

1 The idea

  1. Start at the left side of the list.
  2. Compare two adjacent values: the current value and the one immediately to its right.
  3. If the left value is bigger, swap them. Otherwise, leave them alone.
  4. Move one position right and repeat.
  5. After a full pass, the largest value in the unsorted section has reached the end. Repeat for the remaining section.
Memory hook: Bubble Sort moves a large value rightward, one neighboring swap at a time.

2 Your Python implementation

def bubble_sort(num):
    n = len(num)

    for i in range(n):
        for j in range(0, n - i - 1):
            if num[j] > num[j + 1]:
                num[j], num[j + 1] = num[j + 1], num[j]

    return num


numbers = [5, 2, 3, 12, 3, 65, 34, 100, 1, 0]
print(bubble_sort(numbers))

Yes — your code is correct. It sorts the input list in ascending order.

Small improvement: return the sorted list instead of printing inside the function. That lets other code reuse the result. Your original print(list(num)) is valid, but list(num) is unnecessary because num is already a list.

5 Read the important lines

n = len(num)

Count the list elements once. For 10 values, n = 10.

for i in range(n)

The outer loop controls passes through the list.

range(0, n - i - 1)

The inner loop compares adjacent pairs. After each pass, one more largest value is already sorted at the end, so we skip it. The -1 keeps j + 1 within the list.

num[j] > num[j + 1]

Swap only if the left value is greater than its right neighbor. This produces ascending order.

6 Output for your input

Input:

[5, 2, 3, 12, 3, 65, 34, 100, 1, 0]

Sorted output:

[0, 1, 2, 3, 3, 5, 12, 34, 65, 100]

Equal values such as the two 3s remain in their original relative order. That property is called stability.

7 Time complexity — how much work grows?

n means the number of elements. Big O describes how the amount of work grows as n grows; it is not a direct measurement in seconds.

CaseComplexity for your codeWhy?
BestO(n²)This version still makes all passes even if the list is already sorted.
AverageO(n²)Repeated passes compare many neighboring pairs.
WorstO(n²)A reverse-sorted list requires many comparisons and swaps.
Extra spaceO(1)It sorts the existing list and uses only a few extra variables.
Why O(n²)? For n = 5, the basic version makes 4 + 3 + 2 + 1 = 10 comparisons. For n = 10, it makes 45. The comparison count grows roughly like n × n, so we call it quadratic.

Optimized best case: if you add a swapped flag and stop when a pass makes no swaps, an already-sorted list can finish in O(n) time. That optimization is not in your current code.

8 When to use it

  • Learning sorting, loops, comparisons and swapping.
  • Demonstrating how a simple algorithm works on a tiny list.
  • Situations where simplicity matters more than speed and the input is very small.

9 When not to use it

  • Large lists: quadratic work grows quickly.
  • Performance-sensitive production code.
  • Normal Python tasks where sorted() or .sort() is available.

10 Quick summary

Strategy: compare adjacent pairs.

Swap rule: left > right.

Time: O(n²) for this implementation.

Extra space: O(1).

In-place: yes.

Stable: yes.
