Introduction

What is Python

Python is a high-level, interpreted, and general-purpose programming language. It was created by Guido van Rossum and first released in 1991. Python is known for its simplicity, readability, and ease of learning. It supports multiple programming paradigms, including procedural, object-oriented, and functional programming.

Python is widely used in web development, data science, machine learning, automation, scientific computing, and more.

Features of Python

  • Simple and Easy to Learn: Python has a clean and easy-to-read syntax which makes it beginner-friendly.
  • Interpreted: Python code is executed line by line, which makes debugging easier.
  • High-Level Language: Python abstracts complex details of the computer from the programmer.
  • Portable: Python programs can run on any operating system without modification.
  • Extensive Libraries: Python has a vast standard library and many third-party libraries for different tasks.
  • Open Source: Python is free to use and distribute.
  • Dynamic Typing: Variable types are determined at runtime, so you don’t need to declare them explicitly.

To start programming in Python, you need to install it on your computer:

Python vs Other Languages

Python is often compared with languages like Java, C++, and JavaScript. Key differences include:

  • Syntax: Python has a simpler and more readable syntax than Java and C++.
  • Compilation: Python is interpreted, while Java and C++ are compiled.
  • Memory Management: Python uses automatic garbage collection; C++ requires manual memory management.
  • Use Cases: Python is popular in data science, AI, and automation. Java is widely used in enterprise apps. C++ is often used for system programming and game development.

Encapsulation & Abstraction

- Encapsulation: Restrict access to methods and variables using naming conventions (

,

). - Abstraction: Hiding implementation details; achieved using abstract classes (from

# Encapsulation example
class Example:
    def __init__(self):
        self.public = "Accessible"
        self._protected = "Internal use"
        self.__private = "Private"

# print(e.__private) # Error

# Abstraction example
from abc import ABC, abstractmethod
class Shape(ABC):
    @abstractmethod
    def area(self):
        pass

class Square(Shape):
    def __init__(self, side):
        self.side = side
    def area(self):
        return self.side * self.side

s = Square(5)
print(s.area())  # 25

Modules are Python files containing functions, variables, and classes that can be reused. You can import modules using the

Magic Methods (__init__, __str__, __repr__)

Magic methods (also called dunder methods) are special methods in Python with double underscores. They allow customizing object behavior. 

# __init__ : Constructor to initialize objects
class Person:
    def __init__(self, name, age):
        self.name = name
        self.age = age

# __str__ : Returns a human-readable string
    def __str__(self):
        return f"{self.name}, {self.age} years old"

# __repr__ : Returns a string representation used for debugging
    def __repr__(self):
        return f"Person(name={self.name!r}, age={self.age!r})"

p = Person("Alice", 25)
print(p)       # Alice, 25 years old
print(repr(p)) # Person(name='Alice', age=25)

Reading Files

File Modes

Common file modes in Python:

  • "r" : Read (default)
  • "w" : Write (creates or overwrites)
  • "a" : Append
  • "x" : Create (fails if file exists)
  • "b" : Binary mode (e.g., "rb", "wb")
  • "t" : Text mode (default, e.g., "rt", "wt")

Exception Handling

try, except

Exceptions are errors that occur during program execution. You can handle them using 

try
and 
except
blocks to prevent the program from crashing. 

# Example:
try:
    x = 10 / 0
except ZeroDivisionError:
    print("Cannot divide by zero")

else & finally

- else: Runs if no exception occurs in the 

try
block. - finally: Runs always, whether an exception occurs or not. Useful for cleanup tasks. 

try:
    x = 10 / 2
except ZeroDivisionError:
    print("Cannot divide by zero")
else:
    print("Division successful")  # Executes if no exception
finally:
    print("Execution complete")    # Always executes

Raising Exceptions

raise

Custom Exceptions

You can create your own exception classes by inheriting from the built-in 

Exception
class. 

# Example:

    pass

try:
    check_value(-10)
except MyError as e:
    print(e)  # Value cannot be negative

Advanced Topics

Decorators

Decorators are functions that modify the behavior of another function without changing its code. They are often used for logging, access control, or timing functions. 

# Example:
def decorator(func):
    def wrapper():
        print("Before function call")
        func()
        print("After function call")
    return wrapper

@decorator
def say_hello():
    print("Hello!")

say_hello()
# Output:
# Before function call
# Hello!
# After function call

Generators & Iterators

Generators allow you to create iterators with 

yield
, producing values on the fly without storing the entire sequence in memory. 

# Generator example
def generate_numbers(n):
    for i in range(n):
        yield i

for num in generate_numbers(5):
    print(num)  # 0 1 2 3 4

# Iterator example
my_list = [1, 2, 3]
it = iter(my_list)
print(next(it))  # 1

List comprehensions provide a concise way to create lists. 

# Example:

# With condition

# Set comprehension

    name = request.form["name"]
    cursor.execute("INSERT INTO users (name) VALUES (?)", (name,))
    conn.commit()
    return "User added"

@app.route("/users")
def list_users():
    cursor.execute("SELECT * FROM users")
    users = cursor.fetchall()
    return str(users)

def update_user(id):
    name = request.form["name"]
    cursor.execute("UPDATE users SET name=? WHERE id=?", (name, id))
    conn.commit()
    return "User updated"

def delete_user(id):
    cursor.execute("DELETE FROM users WHERE id=?", (id,))

1. Overview

  • Encoding → format conversion (reversible)
  • Encryption → secure data (reversible with key)
  • Hashing → one-way transformation (NOT reversible)

2. Encoding & Decoding

Concept

  • Used to safely transmit data
  • Not secure (no secrecy)

Base64 Encoding


import base64

data = "hello".encode()
encoded = base64.b64encode(data)
print(encoded)

decoded = base64.b64decode(encoded)
print(decoded.decode())

How it Works

  • Converts binary → ASCII
  • Used in APIs, tokens, file transfer

3. Hashing (One-Way Security)

Concept

  • Cannot reverse back
  • Used for passwords

SHA256 Example


import hashlib

data = "password".encode()

hash_value = hashlib.sha256(data).hexdigest()
print(hash_value)

Verify Hash


def verify(input_password, stored_hash):
    return hashlib.sha256(input_password.encode()).hexdigest() == stored_hash

Salted Hashing


salt = "abc123"
hash_value = hashlib.sha256((salt + "password").encode()).hexdigest()
  • Prevents rainbow table attacks

Password Hashing (Best Practice)


from passlib.context import CryptContext

pwd = CryptContext(schemes=["bcrypt"])

hashed = pwd.hash("password")
pwd.verify("password", hashed)

4. Encryption & Decryption

Concept

  • Reversible using key
  • Used for sensitive data

Symmetric Encryption (Same Key)


from cryptography.fernet import Fernet

key = Fernet.generate_key()
cipher = Fernet(key)

encrypted = cipher.encrypt(b"secret data")
print(encrypted)

decrypted = cipher.decrypt(encrypted)
print(decrypted.decode())

How it Works

  • Plaintext → Encrypt → Ciphertext
  • Ciphertext → Decrypt → Plaintext

5. Asymmetric Encryption (Public/Private Key)

  • Public key → encrypt
  • Private key → decrypt

30. Python Architecture: Exception Hierarchy, Modules, Packaging & Environments

Python utilizes a structured runtime environment built on top of modular compilation, exception-driven control flow, and sandboxed package dependency isolation.

A. Exception Hierarchy & Error Propagation Flow

All standard exceptions in Python inherit from the root BaseException. Application and framework-level error handlers should intercept subclasses of Exception rather than BaseException directly to avoid unintentionally trapping system signals like KeyboardInterrupt (Ctrl+C) or SystemExit.

      ├── LookupError (IndexError, KeyError)

B. Modules vs. Packages vs. __init__.py

  • Module: Any single Python source file (.py) containing executable statements, classes, or functions.
  • Regular Package: A physical directory containing an explicit __init__.py file. Importing the package initializes this file, which establishes __all__ public symbols and initializes namespace variables.
  • Namespace Package (PEP 420): A directory split across multiple zip files or file paths without an __init__.py file, allowing disparate sub-packages to merge into a single top-level namespace.

C. Virtual Environments & Pip Packaging Mechanism

  • venv: Creates a light, isolated directory containing a private Python executable copy, dynamic site-packages folder, and activation scripts.
  • Path Resolution (sys.path): When an import is evaluated, Python searches: (1) Current directory, (2) PYTHONPATH environment directories, (3) Standard library path, and (4) Site-packages of the active virtual environment.
  • pip / wheel: Downloads pre-compiled binary distributions (.whl) or builds from source distributions (sdist), verifying hashes from requirements.txt or modern lockfiles.

31. CPython Internals: Compilation, Bytecode, Object Memory & Execution Stack

CPython is the reference implementation of Python, written in C. It compiles human-readable Python code into intermediate Bytecode, which is then interpreted by the CPython Virtual Machine.

A. The CPython Compilation Pipeline

  1. Source Code (.py): Raw ASCII/UTF-8 character stream.
  2. Tokenizer & Parser: Converts source code into an Abstract Syntax Tree (AST).
  3. Bytecode Compiler: Emits platform-independent instruction sets (.pyc cache files inside __pycache__).
  4. CPython Evaluation Loop (_PyEval_EvalFrameDefault): A massive C switch-statement engine that reads bytecode instructions sequentially and modifies the frame evaluation stack.
+--------------------+       +---------------------+       +-----------------------+
| Python Source Code | ====> |  Tokenizer & Parser  | ====> | Abstract Syntax Tree  |
|     (script.py)    |       |      (Tokens)       |       |        (AST)          |
+--------------------+       +---------------------+       +-----------+-----------+
                                                                       |
                                                                       v
+--------------------+       +---------------------+       +-----------------------+
| Native CPU Machine | <==== | CPython Evaluation  | <==== | Python Bytecode (.pyc)|
| Instructions (x86) |       |   Loop (C Engine)   |       | (LOAD_FAST, BINARY_OP)|
+--------------------+       +---------------------+       +-----------------------+

B. Everything is a PyObject

In CPython, every variable, integer, string, function, and class is a pointer to a C heap structure known as PyObject (or PyVarObject for variable-length items like lists/tuples).

A standard PyObject contains two mandatory header fields:

  • ob_refcnt (Reference Count): 64-bit integer tracking active references pointing to this object.
  • ob_type (Type Pointer): A pointer to a PyTypeObject struct determining the object's methods, memory size, and behavior.

C. Mutability vs. Immutability Memory Mechanics

Category Types Memory Behavior on Modification Hashing Capability
Immutable int, float, bool, str, tuple, bytes, frozenset Cannot be mutated in-place. Any modification allocates a new object in heap memory with a new id(). Hashable by default (Can serve as dictionary keys / set members).
Mutable list, dict, set, bytearray, Custom user-defined classes Mutates in-place. Internal memory buffer expands/shrinks while retaining the exact same memory address (id()). Unhashable (Raises TypeError: unhashable type).

D. Stack vs. Heap in CPython

  • C Call Stack: Manages C-level stack frames executing the CPython engine.
  • Python Execution Frame (Heap-allocated): When a Python function is invoked, CPython creates a PyFrameObject on the heap (not on the OS machine stack). This frame contains local variable arrays (fastlocals), evaluation stack pointers, and cell/free variable arrays for closures.
  • Python Values: All Python objects strictly reside inside the Memory Heap. Variables inside functions are simply pointer references residing in the frame's local array pointing to heap addresses.

32. Python Memory Management: Reference Counting, Cyclic GC & The GIL

CPython manages memory automatically through a two-tiered memory architecture combining deterministic Reference Counting with a generational Cyclic Garbage Collector, synchronized under the Global Interpreter Lock (GIL).

A. Primary Memory Management: Reference Counting

  • Every time a name is bound to an object, passed into a function, or appended to a list, its internal ob_refcnt increments by 1.
  • When a variable goes out of scope (e.g. function returns) or is unbound via del, ob_refcnt decrements by 1.
  • Immediate Deallocation: The exact millisecond ob_refcnt == 0, the memory is instantly released back to Python's memory allocator (PyMalloc) without waiting for a GC sweep.

B. Secondary Memory Management: Generational Cyclic GC (`gc` module)

Reference counting alone cannot free objects trapped in reference cycles (e.g., Object A points to Object B, and Object B points back to Object A, but both are unreachable from global/local scope).

  • Generations (0, 1, 2): Objects are placed in Generation 0 upon allocation. If they survive a collection sweep, they are promoted to Generation 1, and eventually to Generation 2 (long-lived objects).
  • Tri-Color Marking Algorithm: Periodically, CPython tracks container objects (lists, dictionaries, custom classes, tuples) and detects isolated subgraphs where references originate exclusively from within the cycle itself.

C. The Global Interpreter Lock (GIL)

  • What it is: A mutual exclusion lock (mutex) used by CPython to prevent multiple native OS threads from executing Python bytecode concurrently.
  • Why it exists: CPython's memory manager is not thread-safe. Without the GIL, concurrent threads modifying ob_refcnt on shared objects would produce race conditions, memory corruption, and undefined behavior.
  • Impact: In pure Python code, multithreading cannot scale across multiple CPU cores for CPU-bound computation. Multiprocessing or native C-extensions (NumPy, PyTorch) that release the GIL must be used instead.

33. Python OOP: Classes, Execution Scope, Variable Namespaces & Method Types

In Python, classes are first-class objects dynamically instantiated at runtime. When a class definition executes, Python constructs an isolated class namespace mapping attributes, functions, and metadata inside a type instance.

A. The Anatomy of Class Construction

  • self: The explicit reference to the current instance passed automatically as the first argument to instance methods. Unlike JavaScript/Java where this is implicit, Python requires explicit binding.
  • __init__ vs __new__: __new__(cls) is the true static constructor that allocates memory for the PyObject in the heap; __init__(self) is the initializer that configures instance state after creation.
  • Instance Variables vs. Class Variables: Instance variables live inside the object's local dictionary (self.__dict__). Class variables live in the shared class dictionary (Class.__dict__) and are shared across all instances until overwritten on an instance.

34. Encapsulation: Name Mangling, Access Conventions & @property

Python does not enforce access control through hardware-level private keywords. Instead, it balances public transparency with naming conventions and compiler-enforced Name Mangling, mediated by the Descriptor Protocol via @property.

A. Access Level Conventions

  • Public (identifier): Fully accessible from any caller inside or outside the module.
  • Protected (_identifier): An API contract convention signaling internal implementation detail. Tooling and linters flag external access, but the runtime does not block it.
  • Private with Name Mangling (__identifier): Any attribute prefixed with two leading underscores and at most one trailing underscore is rewritten by the compiler to _ClassName__identifier to prevent accidental namespace collisions in derived subclasses.

B. The @property Decorator (Getters, Setters & Deleters)

Properties allow developers to expose methods with standard attribute access syntax (e.g. account.balance instead of account.get_balance()), while allowing transparent data validation, lazy evaluation, and access logging behind the scenes.

38. Python Advanced: Iterators, Generators & The yield Mechanism

Python's iteration model relies on two formal structural protocols: the Iterable Protocol and the Iterator Protocol. Together, they enable lazy, memory-constant processing of infinite or massive data sequences.

A. The Protocols Under the Hood

  • Iterable Protocol: An object is iterable if it implements __iter__(), which must return an iterator instance (or implements __getitem__() with consecutive zero-based integer keys).
  • Iterator Protocol: An object is an iterator if it implements:
    • __iter__(): Returns self (so iterators are themselves iterable).
    • __next__(): Returns the next item in sequence. When values are exhausted, it must raise StopIteration.

B. Generators (yield) & Pausable Stack Frames

A generator function is syntactic sugar for creating an iterator without writing boilerplate classes. When a function contains the yield keyword, calling it does not execute the function body; instead, it compiles the code into a Generator Object (PyGenObject).

  • Executing next(gen) resumes execution until the next yield expression is reached, saves the local frame execution state (instruction pointer, local variable values), and yields the value back to the caller.
  • Two-way communication (.send(), .throw(), .close()): Beyond producing data, generators can receive values dynamically via received = yield value.
  • Sub-generator Delegation (yield from iterable): Transparently delegates iteration and two-way channel communication to an inner generator or iterable.

class FibonacciSequenceIterator:
    """Explicit class-based iterator calculating Fibonacci numbers up to a maximum limit."""
    def __init__(self, limit: int):
        self.limit = limit
        self.count = 0
        self.prev = 0
        self.curr = 1

    def __iter__(self):
        return self  # Required: Iterator must return itself on __iter__()

    def __next__(self) -> int:
        if self.count >= self.limit:
            raise StopIteration  # Signals exhaustion to for-loops / comprehensions

        if self.count == 0:
            self.count += 1
            return 0
        elif self.count == 1:
            self.count += 1
            return 1

        next_val = self.prev + self.curr
        self.prev = self.curr
        self.curr = next_val
        self.count += 1
        return next_val

        return result
    return wrapper

def retry_execution(max_retries: int = 3, delay_seconds: float = 0.1):

                        raise
                    time.sleep(delay_seconds)
        return wrapper
    return decorator

40. Context Managers: Resource Management & Exception Boundaries

Context managers establish deterministic setup and teardown lifecycles for resources (files, sockets, database transactions, mutex locks) using the with statement, ensuring teardown logic executes even if unhandled exceptions occur.

A. The Context Management Protocol (__enter__ & __exit__)

  • __enter__(self): Executes setup logic. The return value is bound to the variable following the as clause (if present).
  • __exit__(self, exc_type, exc_val, exc_tb): Executes cleanup logic.
    • If no exception occurred in the with block: all three arguments are None.
    • If an exception occurred: exc_type, exc_val, and exc_tb contain the error metadata.
    • Suppressing Exceptions: If __exit__() returns a truthy value (True), Python suppresses the exception and execution continues normally after the with block. If it returns False or None, the exception propagates up the stack.

B. Generator Context Managers (@contextlib.contextmanager)

Allows context managers to be written as single generator functions where code before yield handles __enter__, and code inside a finally block handles __exit__.

import contextlib

# =========================================================================

class DatabaseTransaction:

        self.is_active = False

    def __enter__(self):
        self.is_active = True
        print(f"[TX {self.connection_id}] Transaction BEGIN.")
        return self  # Bound to the 'as' identifier

            raise RuntimeError("Cannot query on inactive transaction")
        print(f"[TX {self.connection_id}] Executing: {sql}")

    def __exit__(self, exc_type, exc_val, exc_tb) -> Optional[bool]:
        self.is_active = False
        if exc_type is not None:
            # Exception was raised within the 'with' block
            print(f"[TX {self.connection_id}] Transaction ROLLBACK due to: {exc_val}")
            return False  # False = Do NOT suppress error; bubble up

        print(f"[TX {self.connection_id}] Transaction COMMIT.")
        return True

42. Python Concurrency: Processes vs Threads & Synchronization Primitives

Concurrency in Python is split into two primary OS-level execution paradigms: Multithreading (shared address space within a single OS process, bounded by the GIL for CPU tasks) and Multiprocessing (isolated OS processes with separate memory heaps and GIL instances).

A. Multithreading vs Multiprocessing Structural Matrix

Category threading.Thread multiprocessing.Process
Memory Space Shared memory across all threads within the parent process. Isolated memory; each process owns a private virtual address space.
GIL Impact Only 1 thread executes Python bytecode at any given instant. Each process runs its own independent GIL across separate CPU cores.
Creation Overhead Lightweight (~few KB stack memory, fast OS context switch). Heavier (~10–50 MB initialization, fork/spawn overhead).
Communication Direct variable sharing (requires locks to prevent race conditions). IPC (Inter-Process Communication): Queues, Pipes, Shared Memory.
Best Workload I/O-Bound: Network requests, database queries, file reads. CPU-Bound: Number crunching, image rendering, data processing.

B. Thread Synchronization Primitives Reference

  • Lock: Mutual exclusion lock (Mutex). Only one thread can acquire it at a time; others block until released. Non-reentrant (a thread deadlocks if it tries to acquire its own lock twice).
  • RLock (Reentrant Lock): Allows the same thread to acquire the lock multiple times recursively without deadlocking. Must be released the exact same number of times it was acquired.
  • Semaphore: Maintains an internal counter of available permits. Allows up to $N$ threads to access a shared resource concurrently (ideal for connection pools or rate limiters).
  • Event: Communication flag between threads. Threads call event.wait() to block until another thread signals event.set().
  • Condition: Combines a lock with a notification queue. A thread waits (cv.wait()) until another thread notifies (cv.notify() / cv.notify_all()) that a specific state expression evaluates to true.
  • queue.Queue: Thread-safe FIFO/LIFO/Priority queue with built-in locking and condition tracking (task_done(), join()).

43. Multiprocessing: Inter-Process Communication (IPC), Pools & Shared Memory

The multiprocessing module spawns separate operating system processes, each with its own CPython interpreter and memory space, allowing pure Python code to achieve true 100% parallel execution across all CPU cores.

A. Inter-Process Communication (IPC) Mechanisms

  • multiprocessing.Queue: Process-safe FIFO pipe built on top of OS pipes and synchronization primitives. Automatically handles pickle serialization across process boundaries.
  • multiprocessing.Pipe: A direct, fast bidirectional (duplex) or unidirectional communication link between two specific processes returning two connection objects (conn1, conn2).
  • multiprocessing.shared_memory (Python 3.8+): Allocates direct, raw memory segments mapped into the virtual address space of multiple processes, allowing zero-copy data sharing (ideal for NumPy arrays).

B. Process Pools (multiprocessing.Pool vs ProcessPoolExecutor)

Manages a fixed pool of pre-forked worker processes, distributing task queues across cores and aggregating results back to the parent process.

  • pool.map(func, iterable): Synchronous blocking map that chunks data and preserves input order.
  • pool.imap_unordered(func, iterable): Lazy, memory-efficient generator returning results as soon as individual workers complete.

44. Python AsyncIO: Event Loop Architecture, Coroutines, Futures & Tasks

asyncio is Python's standard library framework for writing single-threaded concurrent code using the async/await syntax. It operates via cooperative multitasking, utilizing an event loop to schedule and multiplex thousands of non-blocking I/O operations simultaneously.

A. The Core AsyncIO Architecture

  • Event Loop: The central scheduler and dispatch engine running on the main thread. It monitors I/O readiness sockets (via OS-level primitives like epoll on Linux, kqueue on macOS, or IOCP on Windows), timers, and scheduled task queues.
  • Coroutine (async def): A specialized function that returns a Coroutine Object when called (does not run immediately). It yields control explicitly back to the event loop whenever it encounters an await expression.
  • asyncio.Future: A low-level object representing an eventual result of an asynchronous operation (the exact conceptual equivalent of a JavaScript Promise). It starts in a pending state and transitions to finished or failed when set_result() or set_exception() is called.
  • asyncio.Task: A concrete subclass of Future that wraps and drives a Coroutine. Instantiating a task via asyncio.create_task() schedules the coroutine on the event loop immediately for background execution.

B. Concurrent Orchestration: create_task vs asyncio.gather

Construct Primary Role Scheduling Behavior Error Handling Options
asyncio.create_task(coro) Fires off a background coroutine without blocking the current flow. Schedules coroutine on the active loop immediately as a background task. Attach callback via .add_done_callback() or capture exception upon await task.
asyncio.gather(*aws) Aggregates multiple awaitables and awaits them concurrently to collect all results. Wraps passed coroutines into Tasks and awaits completion of the entire batch. return_exceptions=False (Rejects on first error) vs return_exceptions=True (Captures exceptions as items in the returned list).

45. AsyncIO Cancellation, Timeouts, Async Iterators & Generators

Managing asynchronous lifecycles requires structured mechanisms for aborting hung operations, enforcing maximum duration limits, and lazily consuming infinite or real-time event streams.

A. Task Cancellation Mechanics

  • Calling task.cancel() injects an asyncio.CancelledError directly into the coroutine at its currently paused await point.
  • Coroutines can catch asyncio.CancelledError using standard try...finally blocks to flush resources, close sockets, or save state before re-raising or terminating.

B. Enforcing Timeouts: asyncio.wait_for vs asyncio.timeout

  • asyncio.wait_for(coro, timeout=N): Standard legacy API that awaits an operation for up to $N$ seconds, automatically cancelling the inner task and raising asyncio.TimeoutError if exceeded.
  • async asyncio.timeout(delay) (Python 3.11+): Modern, clean asynchronous context manager providing structured timeout boundaries around entire blocks of code.

C. Asynchronous Iteration Protocols (__aiter__ & __anext__)

Similar to synchronous iterators, asynchronous iterators allow await operations inside sequence stepping. An Async Generator (a function using async def and yield) produces values consumed via async for item in stream:.
